# 1. Общие сведения

## 1.1. Наименование информационной системы

Полное наименование: **«MedTracker» — информационная система учёта результатов медицинских анализов.**

Краткое наименование: **MedTracker**.

Имя проекта Django: `medtracker`, имя приложения предметной области: `analyses`.

## 1.2. Основание для разработки

Лабораторная работа №2 «Разработка web-приложения» по дисциплине DevOps (индивидуальное задание на разработку ИС).

## 1.3. Назначение системы

MedTracker предназначен для ведения пользователем личной истории медицинских анализов.

**Анализ** — отслеживаемый медицинский показатель, например «Глюкоза», «Гемоглобин», «Холестерин общий»,
«Артериальное давление». У анализа есть название, единица измерения и описание.

**Значение анализа** — результат одной сдачи анализа или одного измерения: значение («5.4», «120/80»,
«отрицательно»), дата и время сдачи, комментарий.

Система позволяет пользователю:

- вести список своих анализов (создание, просмотр, изменение, удаление);
- вносить значения каждого анализа (создание, просмотр, изменение, удаление);
- просматривать все значения выбранного анализа в хронологическом порядке.

## 1.4. Цели создания системы

1. Хранить результаты медицинских анализов в одной базе данных вместо бумажных бланков и разрозненных файлов.
2. Обеспечить быстрый доступ к истории значений любого анализа.
3. Обеспечить возможность исправлять ошибочно внесённые данные.
4. Разграничить данные пользователей: каждый пользователь работает только со своими анализами.

## 1.5. Область применения

Система предназначена для личного использования (пациентом) и работает в режиме web-приложения:
пользователь работает с системой через браузер, данные хранятся на сервере СУБД.

Система не выполняет автоматический ввод данных из файлов, не ставит диагнозов и не даёт медицинских рекомендаций.

## 1.6. Пользователи системы (роли)

| Роль | Описание |
| --- | --- |
| Гость | Неавторизованный посетитель. Может зарегистрироваться или войти в систему. |
| Пользователь | Зарегистрированный пользователь. Работает со своими анализами и их значениями. |
| Администратор | Пользователь с правами суперпользователя. Работает в административном интерфейсе: управляет учётными записями пользователей, справочником единиц измерения, просматривает и исправляет данные всех пользователей. |

## 1.8. Общая характеристика решения

- Тип системы — web-приложение с клиент-серверной архитектурой.
- Язык и фреймворк — **Python / Django**, архитектурный паттерн MTV (Model — Template — View).
- Пользовательский интерфейс — **динамические web-страницы**, формируемые на сервере шаблонизатором Django
  (Django Templates) по данным из БД; оформление — HTML/CSS.
- СУБД — **PostgreSQL**, развёрнутая на отдельном сервере (Debian 12 в VirtualBox); приложение обращается к ней
  по сети через Django ORM.
- Аутентификация и авторизация — встроенная подсистема Django `django.contrib.auth`.
- Административный интерфейс — встроенный модуль Django `django.contrib.admin`.
