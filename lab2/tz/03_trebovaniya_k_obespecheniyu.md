# 3. Требования к системе в целом и к видам обеспечения

## 3.1. Требования к структуре и функционированию системы

Система состоит из двух узлов:

| Узел | Состав | Функции |
| --- | --- | --- |
| Сервер приложения (рабочая станция Windows) | Python, Django, приложение `analyses` | приём HTTP-запросов, проверка доступа, валидация данных, формирование HTML-страниц, обращение к БД |
| Сервер БД (Debian 12 в VirtualBox) | PostgreSQL | хранение данных, обеспечение целостности (первичные и внешние ключи, ограничения уникальности) |

Клиент — web-браузер пользователя. Взаимодействие: браузер ↔ сервер приложения по HTTP (порт 8000),
сервер приложения ↔ сервер БД по протоколу PostgreSQL (TCP 5432).

**Режимы функционирования:**

- штатный режим — сервер приложения и сервер БД запущены, пользователи работают через браузер;
- режим обслуживания — выполнение миграций, резервное копирование БД; работа пользователей не предусмотрена.

## 3.2. Требования к надёжности

- Целостность данных обеспечивается ограничениями БД: внешние ключи, `NOT NULL`, ограничения уникальности.
- При удалении анализа его значения удаляются каскадно; «висячие» значения без анализа в БД невозможны.
- Операции записи выполняются в транзакциях: при ошибке данные не сохраняются частично.
- При недоступности сервера БД пользователь получает страницу «Сервер базы данных недоступен» (HTTP 503)
  с предложением обновить страницу позже; данные при этом не изменяются. После восстановления связи система
  продолжает работу без перезапуска.
- Резервное копирование БД выполняется утилитой `pg_dump` вручную перед изменением структуры БД.

## 3.3. Требования к безопасности

- Аутентификация по логину и паролю средствами `django.contrib.auth`; сессия хранится в таблице `django_session`,
  идентификатор сессии передаётся в cookie.
- Пароли хранятся только в виде хеша (алгоритм PBKDF2-SHA256 с солью).
- Включены стандартные валидаторы сложности пароля Django (`AUTH_PASSWORD_VALIDATORS`).
- Все запросы к анализам и значениям фильтруются по текущему пользователю (FR-5).
- Все изменяющие операции выполняются только методом POST и защищены CSRF-токеном.
- Ввод пользователя проверяется формами Django; обращения к БД выполняются только через ORM
  (параметризованные запросы, защита от SQL-инъекций).
- Вывод данных в шаблонах экранируется автоматически (защита от XSS).
- Секреты (`SECRET_KEY`, пароль БД) хранятся в файле `.env` и в репозиторий не попадают.
- Пользователь БД приложения не является суперпользователем PostgreSQL и имеет права только на БД приложения.
- Подключение к PostgreSQL разрешено только из подсети сервера приложения (`pg_hba.conf`), метод
  аутентификации `scram-sha-256`.

## 3.4. Требования к эргономике

- Язык интерфейса — русский, включая сообщения об ошибках и административный интерфейс.
- Все страницы построены на общем шаблоне с единой шапкой и навигацией (FR-25).
- Обязательные поля форм отмечены знаком `*`; ошибки выводятся рядом с полем.
- Удаление выполняется только после подтверждения.
- Интерфейс корректно отображается в актуальных версиях Chrome, Firefox, Edge при ширине окна от 360 px.

## 3.5. Требования к производительности

- Время формирования любой страницы при объёме до 10 000 значений у пользователя — не более 1 с.
- Список анализов формируется одним SQL-запросом (количество значений — агрегатом `COUNT`),
  страница анализа — не более чем тремя запросами к таблицам анализов (анализ, количество значений,
  страница значений).
- Значения анализа выводятся постранично (FR-12), поэтому время формирования страницы анализа
  не зависит от общего числа значений.

## 3.6. Требования к эксплуатации и сопровождению

- Установка и запуск описаны в файле `README.md`.
- Настройки подключения к БД задаются переменными окружения (файл `.env`) без изменения исходного кода.
- Изменение структуры БД выполняется только миграциями Django.
- Исходный код хранится в Git-репозитории.

## 3.7. Математическое обеспечение

Специальных математических методов и алгоритмов не требуется. Используются только агрегатные функции СУБД
(подсчёт количества значений анализа) и сортировка.

## 3.8. Информационное обеспечение

- БД PostgreSQL `study`, владелец — пользователь `userdb`.
- Кодировка БД — UTF-8.
- Структура БД создаётся и изменяется **миграциями Django** (`makemigrations` / `migrate`).
- Таблицы предметной области: `analyses_unit`, `analyses_analysis`, `analyses_analysisvalue` (раздел 4).
- Таблицы подсистем Django: `auth_user`, `auth_group`, `auth_permission`, `auth_user_groups`,
  `auth_user_user_permissions`, `django_session`, `django_admin_log`, `django_content_type`, `django_migrations`.
- Дата и время хранятся в UTC (`USE_TZ = True`), отображаются в часовом поясе `Europe/Moscow`.
- Начальное заполнение справочника единиц выполняется миграцией данных (data migration).

## 3.9. Лингвистическое обеспечение

- Язык программирования — Python 3.11+.
- Язык запросов к БД — SQL (генерируется Django ORM).
- Языки разметки и оформления — HTML5, CSS3, язык шаблонов Django (DTL).
- Язык интерфейса пользователя — русский (`LANGUAGE_CODE = "ru"`).
- Кодировка исходных файлов и обмена с браузером — UTF-8.

## 3.11. Техническое обеспечение

| Компонент | Минимальные характеристики |
| --- | --- |
| Рабочая станция (сервер приложения) | x86-64 CPU с аппаратной виртуализацией (VT-x / AMD-V), ОЗУ 8 ГБ, 20 ГБ свободного места на диске |
| Виртуальная машина (сервер БД) | 1 vCPU, 1–2 ГБ ОЗУ, диск 10 ГБ, 1 сетевой адаптер |
| Сеть | локальная сеть или виртуальная сеть VirtualBox (сетевой мост / host-only) |

## 3.12. Сетевое обеспечение

- Сервер приложения и сервер БД находятся в одной IP-сети.
- Сервер БД имеет постоянный (статический) IP-адрес 192.168.1.7, который указывается в настройках приложения (`DB_HOST`).
- `postgresql.conf`: `listen_addresses = '*'` (или IP-адрес сервера БД).
- `pg_hba.conf`: `host study userdb 192.168.1.0/24 scram-sha-256`.
- Порты: 5432/TCP — PostgreSQL; 22/TCP — SSH; 8000/TCP — web-интерфейс на сервере приложения
  (`http://127.0.0.1:8000/`).

## 3.13. Организационное обеспечение

| Роль | Обязанности |
| --- | --- |
| Разработчик | разработка и сопровождение приложения, ведение репозитория |
| Администратор БД | установка и настройка PostgreSQL, создание БД и пользователя, резервное копирование |
| Администратор системы | управление пользователями и справочником единиц через `/admin/` |
| Пользователь | ведение своих анализов и их значений |

В рамках лабораторной работы все роли, кроме роли пользователя, выполняет разработчик.

## 3.14. Требования к документированию

- `README.md`: назначение системы, требования к окружению, порядок установки, настройки `.env`,
  команды миграции и запуска, создание администратора.
- `.env.example`: перечень переменных окружения без реальных значений.
- `requirements.txt`: список зависимостей с версиями.
- Отчёт по лабораторной работе с настоящим техническим заданием.
