# 5. Пользовательский интерфейс, архитектура и порядок приёмки

## 5.1. Принцип построения интерфейса

Интерфейс — **динамические web-страницы Django**:

- на каждый запрос представление (View) получает данные из PostgreSQL через ORM и передаёт их в шаблон (context);
- шаблон Django (`{% extends "base.html" %}`, `{% for %}`, `{% if %}`, `{{ переменная }}`) формирует HTML на сервере;
- формы — Django Forms (`ModelForm`), отправка методом POST с CSRF-токеном, после успешного сохранения —
  перенаправление;
- одноразовые сообщения об успешных действиях — `django.contrib.messages`;
- оформление — CSS-файл в каталоге `static/`.

## 5.2. Карта страниц

| URL | Имя маршрута | Метод | Страница | Требования |
| --- | --- | --- | --- | --- |
| `/` | `home` | GET | перенаправление на `/analyses/` | — |
| `/accounts/signup/` | `signup` | GET, POST | регистрация | FR-1 |
| `/accounts/login/` | `login` | GET, POST | вход | FR-2 |
| `/accounts/logout/` | `logout` | POST | выход | FR-3 |
| `/analyses/` | `analysis_list` | GET | список анализов (+ поиск `?q=`) | FR-6, FR-7 |
| `/analyses/add/` | `analysis_create` | GET, POST | создание анализа | FR-8 |
| `/analyses/<id>/` | `analysis_detail` | GET | анализ и таблица его значений | FR-9, FR-12 |
| `/analyses/<id>/edit/` | `analysis_update` | GET, POST | изменение анализа | FR-10 |
| `/analyses/<id>/delete/` | `analysis_delete` | GET, POST | подтверждение и удаление анализа | FR-11 |
| `/values/add/` | `value_create` | GET, POST | добавление значения (анализ выбирается) | FR-13 |
| `/analyses/<id>/values/add/` | `analysis_value_create` | GET, POST | добавление значения выбранного анализа | FR-13 |
| `/values/<id>/edit/` | `value_update` | GET, POST | изменение значения | FR-14 |
| `/values/<id>/delete/` | `value_delete` | GET, POST | подтверждение и удаление значения | FR-15 |
| `/admin/` | — | — | административный интерфейс | FR-19 – FR-22 |

Все страницы, кроме `/accounts/login/` и `/accounts/signup/`, требуют авторизации (FR-4).

## 5.4. Архитектура

```text
┌──────────────── Сервер приложения (Windows) ────────────────┐
│ Браузер ── HTTP :8000 ──► Django (manage.py runserver)      │
│                           ├─ urls.py      маршрутизация     │
│                           ├─ views.py     обработка запроса │
│                           ├─ forms.py     валидация         │
│                           ├─ models.py    ORM               │
│                           └─ templates/   HTML              │
└───────────────────────────┬─────────────────────────────────┘
                            │ psycopg2, TCP :5432
┌───────────────────────────▼─────────────────────────────────┐
│ Сервер БД: Debian 12 (VirtualBox)                           │
│ PostgreSQL 17 — БД study                                    │
└─────────────────────────────────────────────────────────────┘
```

Обработка запроса (паттерн MTV):

```text
Браузер → urls.py → View → (Form: валидация) → Model/ORM → PostgreSQL
                      ↓
                   Template (context) → HTML → Браузер
```

## 5.6. Административный интерфейс

| Модель | Столбцы списка | Фильтры | Поиск |
| --- | --- | --- | --- |
| User | стандартный `UserAdmin` | «Активен», «Статус персонала» | логин |
| Unit | name, note | note | name |
| Analysis | name, user, unit, created_at | user, unit | name |
| AnalysisValue | analysis, владелец (`analysis__user`), value, measured_at, note | analysis__user, measured_at | analysis__name, value, note |

## 5.7. Порядок приёмки

| № | Проверка | Ожидаемый результат | Требования |
| --- | --- | --- | --- |
| 1 | `python manage.py migrate` | в БД на сервере Debian созданы таблицы (видны в `psql`, `\dt`), справочник единиц заполнен | FR-17, FR-23 |
| 2 | Открыть `/analyses/` без входа | перенаправление на `/accounts/login/?next=/analyses/` | FR-4 |
| 3 | Зарегистрироваться | создан пользователь, выполнен вход, открыт пустой список анализов | FR-1 |
| 4 | Создать анализ «Глюкоза», ед. «ммоль/л» | открыта страница анализа, сообщение «Анализ добавлен» | FR-8, FR-18 |
| 5 | Создать анализ «глюкоза» повторно | ошибка «Анализ с таким названием уже существует» | FR-8 |
| 6 | Добавить три значения анализа | значения видны в таблице, новые сверху; записи есть в `analyses_analysisvalue` | FR-12, FR-13, FR-23 |
| 7 | Добавить значение с датой в будущем | ошибка у поля даты, запись не создана | FR-13, FR-24 |
| 8 | Изменить значение | в таблице новое значение | FR-14 |
| 9 | Удалить значение | после подтверждения значение исчезло из таблицы и БД | FR-15 |
| 10 | Изменить название анализа | новое название в списке и на странице анализа | FR-10 |
| 11 | Удалить анализ со значениями | анализ и его значения удалены из БД | FR-11 |
| 12 | Под вторым пользователем открыть ссылку на анализ первого | ответ 404 | FR-5 |
| 13 | Войти в `/admin/` суперпользователем, добавить единицу, заблокировать пользователя | единица доступна в формах, заблокированный пользователь не может войти | FR-19 – FR-21 |
| 14 | Войти в `/admin/` обычным пользователем | доступ запрещён | FR-19 |
| 15 | Проверить репозиторий | нет `.env`, виртуального окружения, паролей | 3.3 |
