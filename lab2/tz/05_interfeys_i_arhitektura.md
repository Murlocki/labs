# 5. Пользовательский интерфейс, архитектура и порядок приёмки

## 5.1. Принцип построения интерфейса

Интерфейс — **динамические web-страницы Django**:

- на каждый запрос представление (View) получает данные из PostgreSQL через ORM и передаёт их в шаблон (context);
- шаблон Django (`{% extends "base.html" %}`, `{% for %}`, `{% if %}`, `{{ переменная }}`) формирует HTML на сервере;
  браузер получает готовую страницу, JavaScript для работы интерфейса не требуется;
- формы — Django Forms (`ModelForm`), отправка методом POST с CSRF-токеном, после успешного сохранения —
  перенаправление;
- одноразовые сообщения об успешных действиях — `django.contrib.messages`;
- оформление — один CSS-файл `static/analyses/style.css`.

**Общие элементы всех пользовательских страниц** (шаблон `base.html`):

| Элемент | Описание |
| --- | --- |
| Заголовок вкладки браузера | «<название страницы> — MedTracker» |
| Шапка | белая полоса во всю ширину: слева «MedTracker» и ссылки навигации, справа имя пользователя и кнопка «Выйти» (FR-25) |
| Блок сообщений | под шапкой; зелёная плашка с текстом сообщения об успехе (6.4); исчезает при следующем переходе |
| Основная область | ширина до 1000 px по центру, отступы 16 px по бокам |
| Кнопки | основная — синяя с белым текстом; второстепенная — белая с синей рамкой; опасная (удаление) — красная |
| Поля формы | подпись над полем, `*` у обязательных, подсказка серым под полем, ошибка красным под полем, красная рамка у поля с ошибкой |

**Адаптивность:** при ширине окна от 360 px страница не прокручивается по горизонтали: ссылки шапки переносятся
на новую строку, кнопки переносятся друг под друга, таблицы прокручиваются по горизонтали внутри своего блока.

## 5.2. Карта страниц

| URL | Имя маршрута | Метод | Доступ | Страница | Требования |
| --- | --- | --- | --- | --- | --- |
| `/` | `home` | GET | все | перенаправление на `/analyses/` | FR-25 |
| `/accounts/signup/` | `signup` | GET, POST | гость | регистрация | FR-1 |
| `/accounts/login/` | `login` | GET, POST | гость | вход | FR-2 |
| `/accounts/logout/` | `logout` | POST | пользователь | выход | FR-3 |
| `/analyses/` | `analysis_list` | GET | пользователь | список анализов (+ поиск `?q=`) | FR-6, FR-7 |
| `/analyses/add/` | `analysis_create` | GET, POST | пользователь | создание анализа | FR-8 |
| `/analyses/<id>/` | `analysis_detail` | GET | владелец | анализ и таблица его значений (+ страница `?page=`) | FR-9, FR-12 |
| `/analyses/<id>/edit/` | `analysis_update` | GET, POST | владелец | изменение анализа | FR-10 |
| `/analyses/<id>/delete/` | `analysis_delete` | GET, POST | владелец | подтверждение и удаление анализа | FR-11 |
| `/values/add/` | `value_create` | GET, POST | пользователь | добавление значения (анализ выбирается) | FR-13 |
| `/analyses/<id>/values/add/` | `analysis_value_create` | GET, POST | владелец анализа | добавление значения выбранного анализа | FR-13 |
| `/values/<id>/edit/` | `value_update` | GET, POST | владелец | изменение значения | FR-14 |
| `/values/<id>/delete/` | `value_delete` | GET, POST | владелец | подтверждение и удаление значения | FR-15 |
| `/admin/` | — | — | персонал | административный интерфейс | FR-19 – FR-22 |

«Владелец» — пользователь, которому принадлежит объект; для остальных пользователей адрес возвращает 404.

## 5.3. Описание экранов

### Э1. Вход — `/accounts/login/`

- **Вкладка:** «Вход — MedTracker».
- **Элементы:** карточка по центру шириной до 420 px; заголовок «Вход в MedTracker»; поля «Имя пользователя *»,
  «Пароль *» (ввод скрыт); кнопка «Войти»; строка «Нет учётной записи? Регистрация».
- **Состояния:** начальное (пустые поля, курсор в поле имени); ошибка — красная плашка над полями
  «Неверный логин или пароль.», имя сохранено.
- **Переходы:** успешный вход → `next` или `/analyses/`; «Регистрация» → Э2.

```text
┌──────────────────────────────────┐
│ Вход в MedTracker                │
│ Имя пользователя *               │

```

### Э9. Сервер базы данных недоступен

- **Когда показывается:** на любой адрес, если при обработке запроса не удалось подключиться к PostgreSQL (6.6).
- **Код ответа:** 503.
- **Элементы:** шапка только с названием «MedTracker» (без ссылок и имени пользователя — они требуют обращения к БД);
  заголовок «Сервер базы данных недоступен»; текст «Не удалось подключиться к базе данных. Данные не изменены.»;
  серый текст «Попробуйте обновить страницу через несколько минут. Если ошибка повторяется, обратитесь
  к администратору.»; кнопка «Обновить страницу» (повторяет текущий адрес).

### Э10. Страница не найдена (404)

- **Когда показывается:** адрес не существует; объект не существует или принадлежит другому пользователю (FR-5).
  Используется при `DEBUG=False`; в режиме отладки Django показывает отладочную страницу.
- **Элементы:** общая шапка; карточка «Страница не найдена», текст «Запрошенная страница не существует или у вас
  нет к ней доступа.», кнопка «Мои анализы».

### Э11. Форма устарела (403)

- **Когда показывается:** отправлена форма без корректного CSRF-токена (FR-24).
- **Элементы:** шапка только с названием «MedTracker»; заголовок «Форма устарела»; текст «Не удалось проверить
  подлинность отправленной формы. Данные не сохранены.»; серый текст «Вернитесь назад, обновите страницу
  и отправьте форму ещё раз.»; кнопка «Мои анализы».

## 5.4. Схема переходов между страницами

```text
                    ┌──────────────┐  «Регистрация»  ┌──────────────┐
   гость ─────────► │ Э1 Вход      │ ◄─────────────► │ Э2 Регистр.  │
                    └──────┬───────┘   «Вход»        └──────┬───────┘
                           │ успешный вход                  │ успешная регистрация
                           ▼                                ▼
                    ┌─────────────────────────────────────────────────┐
         ┌─────────►│ Э3 Мои анализы (поиск ?q=)                      │◄───────────┐
         │          └───┬─────────────┬───────────────┬───────────────┘            │
         │  название    │   «+ Добавить │ «Изменить»    │ «Удалить»                 │ удалено /
         │              ▼   анализ»     ▼               ▼                           │ «Отмена»
         │   ┌───────────────────┐  ┌────────────┐  ┌───────────────────────┐      │
         │   │ Э4 Анализ (?page=)│◄─┤ Э5 Форма   │  │ Э7 Удаление анализа   │──────┘
         │   │                   │  │   анализа  │  └───────────────────────┘
         │   └──┬──────┬──────┬──┘  └────────────┘
         │      │      │      │ «Удалить» в строке
         │      │      │      ▼
         │      │      │   ┌───────────────────────┐   удалено / «Отмена» → Э4
         │      │      │   │ Э8 Удаление значения  │
         │      │      │   └───────────────────────┘
         │      │      │ «+ Добавить значение», «Изменить» в строке
         │      │      ▼
         │      │   ┌───────────────────┐   сохранено / «Отмена» → Э4
         │      │   │ Э6 Форма значения │
         │      │   └───────────────────┘
         └──────┘ «← Мои анализы»

   Из любой страницы: «Мои анализы» → Э3; «+ Добавить значение» → Э6; «Выйти» → Э1;
   «Администрирование» (персонал) → /admin/.
```

## 5.5. Архитектура

```text
┌──────────────── Сервер приложения (Windows) ────────────────┐
│ Браузер ── HTTP :8000 ──► Django (manage.py runserver)      │
│                           ├─ urls.py      маршрутизация     │
│                           ├─ views.py     обработка запроса │
│                           ├─ forms.py     валидация         │
│                           ├─ models.py    ORM               │
│                           └─ templates/   HTML              │
└───────────────────────────┬─────────────────────────────────┘
                            │ psycopg2, TCP :5432
┌───────────────────────────▼─────────────────────────────────┐
│ Сервер БД: Debian 12 (VirtualBox)                           │
│ PostgreSQL 17 — БД study                                    │
└─────────────────────────────────────────────────────────────┘
```

Обработка запроса (паттерн MTV) подробно описана в разделе 6.1:

```text
Браузер → Middleware → urls.py → View → (Form: валидация) → Model/ORM → PostgreSQL
                                   ↓
                                Template (context) → HTML → Браузер
```
