# 2. Функциональные требования

## 2.0. Условные обозначения

**Приоритет:**

- **M** (Must) — обязательное требование, входит в первую очередь реализации;
- **S** (Should) — желательное требование;
- **C** (Could) — требование на перспективу.

Формат дат в интерфейсе: `ДД.ММ.ГГГГ`, даты и времени: `ДД.ММ.ГГГГ ЧЧ:ММ`.

Все требования разделов 2.2–2.4 выполняются только для авторизованного пользователя и только
над его собственными данными (см. FR-5).

---

## 2.1. Регистрация, вход и разграничение доступа

### FR-1. Регистрация пользователя — S

- **Актор:** гость.
- **Описание:** гость создаёт учётную запись на странице регистрации.
- **Входные данные:**

  | Поле | Обязательное | Правила |
  | --- | :---: | --- |
  | Логин | да | до 150 символов; буквы, цифры и `@ . + - _`; уникален в системе |
  | Пароль | да | не короче 8 символов; не только из цифр; не слишком распространённый; не похож на логин |
  | Подтверждение пароля | да | совпадает с паролем |

- **Результат:** учётная запись создана, пароль сохранён в виде хеша, выполнен автоматический вход,
  пользователь перенаправлен на список анализов.
- **Ошибки:** логин занят; пароли не совпадают; пароль не прошёл проверку сложности — форма показывается
  повторно с сообщениями у полей, введённый логин сохраняется.

### FR-2. Вход в систему — M

- **Актор:** гость.
- **Входные данные:** логин, пароль.
- **Результат:** создаётся сессия, пользователь перенаправляется на страницу, которую запрашивал до входа
  (параметр `next`), иначе — на список анализов.
- **Ошибки:** неверный логин или пароль, заблокированная учётная запись — сообщение
  «Неверный логин или пароль», сессия не создаётся.

### FR-3. Выход из системы — M

- **Актор:** пользователь.
- **Описание:** кнопка «Выйти» в шапке любой страницы; выход выполняется POST-запросом.
- **Результат:** сессия завершается, пользователь перенаправляется на страницу входа.

### FR-4. Ограничение доступа для гостей — M

- Все страницы, кроме страниц входа и регистрации, доступны только авторизованному пользователю.
- При обращении гостя к закрытой странице он перенаправляется на страницу входа с параметром `next`,
  содержащим адрес исходной страницы.

### FR-5. Разграничение данных пользователей — M

- Пользователь видит, изменяет и удаляет только анализы, созданные им, и значения этих анализов.
- В выпадающих списках и таблицах выводятся только данные текущего пользователя.
- Обращение по прямой ссылке к анализу или значению другого пользователя возвращает ответ **404 «Не найдено»**.

## 2.2. Анализы

### FR-6. Просмотр списка анализов — M

- **Актор:** пользователь.
- **Описание:** страница «Мои анализы» выводит таблицу всех анализов пользователя. Данные загружаются из БД
  при каждом открытии страницы.
- **Состав таблицы:**

  | Столбец | Содержимое |
  | --- | --- |
  | Название | название анализа, ссылка на страницу анализа (FR-9) |
  | Единица измерения | название единицы или «—», если не указана |
  | Количество значений | число внесённых значений анализа |
  | Действия | ссылки «Изменить» (FR-10) и «Удалить» (FR-11) |

- **Сортировка:** по названию в алфавитном порядке.
- **Над таблицей:** кнопка «Добавить анализ» (FR-8).
- **Пустой список:** выводится сообщение «У вас пока нет анализов» и ссылка «Добавить анализ».

### FR-7. Поиск анализа по названию — S

- На странице списка анализов есть поле поиска.
- Поиск выполняется по вхождению подстроки в название без учёта регистра (GET-параметр `q`).
- Если ничего не найдено, выводится сообщение «Ничего не найдено» и ссылка «Сбросить поиск».

### FR-8. Создание анализа — M

- **Актор:** пользователь.
- **Входные данные:**

  | Поле | Обязательное | Правила |
  | --- | :---: | --- |
  | Название | да | 1–128 символов, начальные и конечные пробелы удаляются; уникально среди анализов пользователя без учёта регистра |
  | Единица измерения | нет | выбирается из справочника единиц (FR-17) |
  | Описание | нет | до 2000 символов (например, референсные значения, условия сдачи) |

- **Результат:** анализ сохраняется в БД с привязкой к текущему пользователю; пользователь перенаправляется
  на страницу созданного анализа; выводится сообщение «Анализ добавлен».
- **Ошибки:** пустое название; название длиннее 128 символов; анализ с таким названием уже есть —
  «Анализ с таким названием уже существует». Форма показывается повторно, введённые данные сохраняются.

### FR-9. Просмотр анализа — M

- **Актор:** пользователь.
- **Описание:** страница анализа содержит:
  - название, единицу измерения, описание, дату создания анализа;
  - кнопки «Изменить анализ», «Удалить анализ», «Добавить значение»;
  - таблицу значений анализа (FR-12).

### FR-10. Изменение анализа — M

- **Актор:** пользователь.
- **Описание:** форма изменения открывается заполненной текущими данными анализа.
- **Входные данные и проверки:** как в FR-8 (при проверке уникальности текущий анализ не учитывается).
- **Результат:** изменения сохраняются в БД; пользователь перенаправляется на страницу анализа;
  выводится сообщение «Анализ изменён».
- **Кнопка «Отмена»:** возврат на страницу анализа без сохранения.

### FR-11. Удаление анализа — M

- **Актор:** пользователь.
- **Описание:** удаление выполняется в два шага: страница подтверждения → POST-запрос.
- **Страница подтверждения** содержит название анализа и предупреждение:
  «Будут также удалены все значения этого анализа (N шт.). Действие необратимо.»
  и кнопки «Удалить» и «Отмена».
- **Результат:** анализ и все его значения удаляются из БД (каскадно); пользователь перенаправляется
  на список анализов; выводится сообщение «Анализ удалён».

## 2.3. Значения анализа

### FR-12. Просмотр значений анализа — M

- **Актор:** пользователь.
- **Описание:** на странице анализа (FR-9) выводится таблица всех его значений из БД.
- **Состав таблицы:**

  | Столбец | Содержимое |
  | --- | --- |
  | Дата и время | дата и время сдачи анализа |
  | Значение | значение и единица измерения анализа |
  | Комментарий | комментарий или пусто |
  | Действия | ссылки «Изменить» (FR-14) и «Удалить» (FR-15) |

- **Сортировка:** по дате и времени сдачи, новые сверху.
- **Пустая таблица:** выводится сообщение «Значений пока нет» и ссылка «Добавить значение».

### FR-13. Добавление значения анализа — M

- **Актор:** пользователь.
- **Способы открытия формы:**
  - кнопка «Добавить значение» на странице анализа — поле «Анализ» заполнено этим анализом;
  - общая кнопка «Добавить значение» в шапке — анализ выбирается из выпадающего списка анализов пользователя.
- **Входные данные:**

  | Поле | Обязательное | Правила |
  | --- | :---: | --- |
  | Анализ | да | только анализы текущего пользователя |
  | Значение | да | 1–64 символа, пробелы по краям удаляются; допускается нечисловое значение (FR-16) |
  | Дата и время сдачи | да | по умолчанию — текущие дата и время; не позже текущего момента |
  | Комментарий | нет | до 255 символов (лаборатория, «натощак» и т.п.) |

- **Результат:** значение сохраняется в БД; пользователь перенаправляется на страницу анализа, в таблице
  которого появилось новое значение; выводится сообщение «Значение добавлено».
- **Ошибки:** пустое значение; дата в будущем — «Дата сдачи не может быть в будущем»; анализ не выбран.
  Форма показывается повторно, введённые данные сохраняются.

### FR-14. Изменение значения анализа — M

- **Актор:** пользователь.
- **Описание:** форма изменения открывается заполненной текущими данными значения.
- **Входные данные и проверки:** как в FR-13; анализ можно сменить на другой анализ того же пользователя.
- **Результат:** изменения сохраняются; пользователь перенаправляется на страницу анализа;
  выводится сообщение «Значение изменено».

### FR-15. Удаление значения анализа — M

- **Актор:** пользователь.
- **Описание:** страница подтверждения с датой и значением («Удалить значение 5.4 ммоль/л от 27.09.2026 10:30?»)
  и кнопками «Удалить» и «Отмена»; удаление — POST-запросом.
- **Результат:** значение удаляется из БД; пользователь перенаправляется на страницу анализа;
  выводится сообщение «Значение удалено».

### FR-16. Хранение нечисловых значений — M

- Значение анализа хранится как строка, чтобы поддерживать результаты вида «120/80», «< 0.5», «отрицательно»,
  «не обнаружено».
- Система не выполняет арифметических преобразований значения.

---

## 2.4. Справочник единиц измерения

### FR-17. Справочник единиц измерения — M

- Система содержит общий для всех пользователей справочник единиц измерения.
- При установке справочник заполняется начальными данными (см. раздел 4.6).
- Пользователи используют справочник только для выбора; изменяет его администратор (FR-21).

### FR-18. Выбор единицы измерения анализа — M

- В формах создания и изменения анализа единица выбирается из выпадающего списка справочника,
  отсортированного по названию; допускается пустое значение «— не указана —».
- При удалении единицы из справочника у анализов, которые её использовали, единица становится пустой;
  сами анализы и их значения сохраняются.

## 2.5. Администрирование

Реализуется встроенным модулем `django.contrib.admin` по адресу `/admin/`.

### FR-19. Доступ к административному интерфейсу — M

- Вход в `/admin/` разрешён только пользователям с признаком «Статус персонала» (`is_staff`).
- Первый администратор создаётся командой `python manage.py createsuperuser`.

### FR-20. Управление пользователями — M

- Просмотр списка пользователей с поиском по логину и фильтрами «Активен», «Статус персонала».
- Создание пользователя, смена пароля, изменение данных.
- Блокировка пользователя снятием признака «Активен» (`is_active`); заблокированный пользователь не может войти.

### FR-21. Управление справочником единиц измерения — M

- Просмотр, создание, изменение и удаление единиц измерения.
- Название единицы уникально; при попытке создать дубликат выводится ошибка.

### FR-22. Управление анализами и значениями всех пользователей — S

- Список анализов: название, владелец, единица, дата создания; фильтры по владельцу и единице; поиск по названию.
- Список значений: анализ, владелец, значение, дата сдачи, комментарий; фильтры по владельцу и дате сдачи;
  поиск по названию анализа, значению и комментарию.
- Изменение и удаление любых записей.

---

## 2.6. Общие требования к обработке данных

### FR-23. Сохранение данных — M

- Все данные хранятся в БД PostgreSQL; обращения к БД выполняются через Django ORM.
- Каждая операция создания, изменения и удаления выполняется в одной транзакции.

### FR-24. Обработка форм — M

- Все формы отправляются методом POST.
- После успешной обработки выполняется перенаправление (схема POST → Redirect → GET), чтобы обновление
  страницы в браузере не приводило к повторной отправке формы.
- Об успешном действии пользователь информируется одноразовым сообщением вверху страницы.
- При ошибках проверки форма показывается повторно с сообщениями у соответствующих полей,
  введённые данные не теряются.

### FR-25. Навигация — M

- Шапка каждой страницы содержит: название системы (ссылка на список анализов), ссылки «Мои анализы»
  и «Добавить значение», логин текущего пользователя и кнопку «Выйти»; для гостя — ссылки «Вход» и «Регистрация».
- Для администратора в шапке дополнительно выводится ссылка «Администрирование».

## 2.8. Пример сценария: добавление значения анализа

```text
Пользователь входит через /accounts/login/                      (FR-2)
    ↓ создаётся сессия
Открывает /analyses/ → выбирает «Глюкоза»                         (FR-6, FR-9)
    ↓
Нажимает «Добавить значение» → /analyses/3/values/add/            (FR-13)
    ↓ вводит 5.4, дату 27.09.2026 08:30, комментарий «натощак»
    ↓ POST (CSRF-токен)
View: проверка авторизации и владельца → валидация формы          (FR-4, FR-5, FR-24)
    ↓ ORM: AnalysisValue.objects.create(...)
PostgreSQL: INSERT INTO analyses_analysisvalue                     (FR-23)
    ↓ redirect 302
/analyses/3/ → в таблице первой строкой «27.09.2026 08:30 | 5.4 ммоль/л | натощак»
```
